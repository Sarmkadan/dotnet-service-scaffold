# ProblemDetailsFactory

Provides a convenient way to create `ProblemDetails` objects that conform to RFC 7807, allowing consistent error payloads across the application.

## API

### CreateProblemDetails (overload 1)

**Purpose**  
Creates a new `ProblemDetails` instance populated with the supplied values.

**Parameters**  
- `statusCode` `int` – The HTTP status code for the problem.  
- `title` `string?` – A short summary of the problem type.  
- `detail` `string?` – A human‑specific explanation of this occurrence.  
- `type` `string?` – A URI that identifies the problem type.  
- `instance` `string?` – A URI that identifies the specific occurrence.  
- `extensions` `IDictionary<string, object?>?` – Additional members to include in the payload.

**Return value**  
A `ProblemDetails` object with the specified properties set; any null arguments result in the corresponding property being left null (or an empty dictionary for `extensions`).

**Exceptions**  
- `ArgumentOutOfRangeException` if `statusCode` is less than 100 or greater than 999.  
- No other exceptions are thrown under normal usage.

### CreateProblemDetails (overload 2)

**Purpose**  
Creates a `ProblemDetails` instance, optionally pulling values such as the trace identifier or request path from the supplied `HttpContext`.

**Parameters**  
- `httpContext` `HttpContext` – The context of the current request; used to fill missing values like `Instance`.  
- `statusCode` `int?` – Optional HTTP status code.  
- `title` `string?` – Optional short summary.  
- `detail` `string?` – Optional detailed message.  
- `type` `string?` – Optional type URI.  
- `instance` `string?` – Optional instance URI; if null, the factory may derive a value from `httpContext`.  
- `extensions` `IDictionary<string, object?>?` – Optional additional members.

**Return value**  
A `ProblemDetails` object initialized with the provided values and any values inferred from `httpContext`.

**Exceptions**  
- `ArgumentNullException` if `httpContext` is `null`.  
- `ArgumentOutOfRangeException` if a non‑null `statusCode` is outside the 100‑999 range.

### Type

**Purpose**  
Gets or sets a URI reference that identifies the problem type according to RFC 7807.

**Remarks**  
May be `null`; when present, it should be a dereferenceable URI that provides human‑readable documentation for the error condition.

### Title

**Purpose**  
Gets or sets a short, human‑readable summary of the problem type.

**Remarks**  
Should be consistent for a given `Type` (e.g., all 400 errors might share the same title). May be `null`.

### Status

**Purpose**  
Gets or sets the HTTP status code generated by the server for this occurrence of the problem.

**Remarks**  
May be `null` when the status code is unknown or not applicable.

### Detail

**Purpose**  
Gets or sets a human‑readable explanation specific to this occurrence of the problem.

**Remarks**  
Can be used to convey debugging information; may contain sensitive data, so consider the audience. May be `null`.

### Instance

**Purpose**  
Gets or sets a URI reference that identifies the specific occurrence of the problem.

**Remarks**  
Often set to the request URI or a unique identifier for the request. May be `null`.

### Extensions

**Purpose**  
Gets or sets a dictionary of additional members to be included in the problem details payload.

**Remarks**  
Keys are strings; values can be any object, including `null`. If `null` is supplied, the factory treats it as an empty dictionary. The returned `ProblemDetails` instance exposes this dictionary directly; callers should avoid mutating it after the object has been serialized if immutability is required.

## Usage

### Example 1: Manual creation

```csharp
var problem = ProblemDetailsFactory.CreateProblemDetails(
    statusCode: 400,
    title: "Validation error",
    detail: "One or more validation errors occurred.",
    extensions: new Dictionary<string, object?>
    {
        ["errors"] = validationErrors
    });
```

### Example 2: Using HttpContext to enrich the payload

```csharp
var problem = ProblemDetailsFactory.CreateProblemDetails(
    httpContext: HttpContext,
    statusCode: 404,
    title: "Resource not found",
    instance: HttpContext.Request.Path);
```

## Notes

- The factory methods are thread‑safe; they only read their input parameters and return a new `ProblemDetails` instance on each call.  
- Supplying `null` for `extensions` results in an empty `Extensions` dictionary on the created object.  
- If `httpContext` is provided, the factory may use `HttpContext.TraceIdentifier` or `HttpContext.Request.Path` to populate `Instance` when the caller leaves it `null`.  
- Setting `Status` to `null` leaves the property unset; serializers will omit the `status` field, which consumers should interpret as an unknown status.  
- All string‑valued properties (`Type`, `Title`, `Detail`, `Instance`) may be left `null`; according to RFC 7807, absent members are omitted from the JSON representation.  
- Mutating the `Extensions` dictionary after the `ProblemDetails` instance has been passed to a serializer can affect the output; treat the dictionary as immutable after creation if consistent payloads are required.
